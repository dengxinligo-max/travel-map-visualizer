# 地图海报的排版与验收

## 参考视觉的可复用部分

画面是完整地图上的编辑排版：顶部极醒目的中文标题，下方保留地理关系；两侧景点短注通过虚线引到真实位置，底部用少量路线卡片收束。信息密度来自清晰层级，不来自把字号不断缩小。

配色由用户在六套主题中选择，或按其自定义要求设置；见 [风格选择](styles.md)。基础渲染器的米白、深绿、黄色是待套色的初始模板，不是未经询问的默认成品。重点景点、路线、水域、文字和信息卡统一应用主题；优先级同时用图例/文字表达，不能只靠颜色。

1080 宽画布：外边距 32–42，标题 80–110，标签 20–24，说明 17–20，页脚至少约 13。默认 PNG 2 倍导出不等于可以缩小逻辑字号。

## 三类地图的差别

| 类型 | 主图信息 | 路线卡片 | 何时拆图 |
|---|---|---|---|
| 区域自驾 | 主干路、水系、区域地名、Day 顺序 | 天数、路段、经核验的里程/时长 | 一组点在主图上挤在 34px 内时加城区详图 |
| 城区漫游 | 街巷、水域、绿地、景点短注 | 半日/整日安排、步行或公交方式 | 多于 8–10 个带长备注的景点，或单侧标签放不下 |
| 多方案 | 不同路线的真实点与半透明路线色带 | A/B/C/D、时间、地区与适合人群 | 超过 4 条路线或相互覆盖太多 |

基础脚本共享骨架，`mode` 不会自动生成完全不同模板。调用 Skill 的模型应根据内容调整标题、底图 profile、路线卡和图幅；需要参考图那种大型行程表或复杂分区时，在模板扩展相应模块，并重新验收。不能宣称一个参数已自动实现不存在的模块。

## 地图信息的优先级

真实地图层 → 行程色带/路线 → 景点引线 → 注释背景 → 真实点与编号 → 方向/比例尺 → 标题和图例 → 来源署名。水域多环应使用 evenodd 保留岛屿；路线经过湖水时，先检查它是示意线还是实际路径，不为“好看”强行改海岸线。

区域路书的地图画布应是完整、连续的地理背景。先确定可读的地图视口，再用同一投影把道路、水系和地形铺到整个视口；纵向路线可能自然只占较窄的一带，但周围仍应有真实地形与地理参照。不能为填满横向空间而拉伸经纬比例。导出后观察四边与角落，区分真实稀疏地区和数据或阴影裁剪造成的空白。

实线道路路线下应能看到真实道路走向，并至少标出主干路路号、相关河湖和沿途县级区划。国道编号取道路 `ref`，河流名称取具名水系几何；县名可用代表点或经核验的沿线区域提示，不能把代表点当行政边界。路号沿线重复少量即可；文字按主题底色设置对比描边，防止压在地形上消失。县级地名与 POI 卡片相撞时移动文字锚点或使用独立的“沿途县区”信息带，不能移动真实景点标记。

道路中心线最短路的每段都要保留可追溯几何和道路吸附距离。景点本身在湖中、山上或大型园区内时，路线只到已证实的车行道路；图面用不同线型标出未核实的最后一段，文字说明不能把它写成可开车抵达。道路里程与原攻略里程并列时明确区分，不能混为同一数据。

引线采用 1–2 个折点，按南北顺序分列排布。至少检查：引线穿越无关标签、标记压住备注、两标记重叠、标题溢出、页面边缘截断。空间不足时扩高、压缩说明或拆图，不改经纬度。

## HTML 与图片保持一致

HTML 的主海报与 PNG 来自同一 SVG。工具条和点选详情位于画布之外，PNG 只导出海报。HTML 允许切换路线、点击景点、重置、下载 SVG/PNG；不依赖在线瓦片或 CDN。保持键盘可操作、明显焦点和文字说明。这里是地图海报，不承诺在线导航、任意地图缩放或实时 POI 搜索。

浏览器截图前加载中文字体；跨设备精确复现时使用许可允许再分发的中文字体并嵌入 SVG/HTML，或记录环境字体。Linux 可用 Noto Sans CJK；字体无法覆盖中文时不要交付方框字 PNG。对内容转换为轮廓的图片保留 HTML 文本等效信息。

## 最小验收记录

在最终输出目录创建 `validation.json`，记录：

- 地图来源、实际获取时间、范围、坐标系与要素数。
- 文字攻略与已上图点的对照；模糊点、示意线、未核验事实。
- HTML 打开、景点点击、路线开关、离线资源、控制台是否已验证。
- PNG 路径与像素大小，以及人工看图结论。
- 仍未执行的检查与原因。使用 true/false/not_run，避免“基本通过”。

完成标准是：用户能打开 HTML，得到清晰 PNG，并了解实际存在的数据限制。缺少真实地图数据时可保留输入、脚本和失败原因，但不能把虚构底图或空白截图当样张交付。
